REQUIREMENTS AND EVIDENCE

Planned AVL replacement -> enhanced/AvlTree.hpp; four rotation tests and three
2,000-record property sequences, checking order against std::map and independent
heights/balance after each insertion.

Existing advising behavior -> original CSV, tests/test_cli.py; seven scenarios
match original/enhanced process output exactly, including lookup, invalid menu
choices, EOF, and both accepted and rejected catalog replacement.

Boundary handling -> tests/test_advising.cpp; 37 test groups cover duplicates,
missing data, prerequisites, stream failure, maximum limits, and rejection while
preserving a known active catalog. Evidence: evidence/test-run.txt.

Complexity and empirical evaluation -> benchmark sources plus generator,
raw five-trial measurements, medians, and environment. Analysis distinguishes
ordered worst cases from randomized overhead and states workload limits.

Outcome 3 -> algorithm selection, invariant reasoning, asymptotic analysis,
measured tradeoffs, and comparison with hash tables/sorted vectors.
Outcome 4 -> complete runnable C++ program, compiler checks, sanitizers, tests,
and reproducible measurements supporting an advising use case.
Outcome 5 -> bounded input, rejection tests, protected active state, and explicit
remaining risks. The safe replacement pattern already existed in the baseline;
this enhancement preserves it and adds measured tests and input limits.
Outcome 2 -> code comments, README, narrative, and understandable measurements.
Outcome 1 -> reviewable design decisions and these focused review questions.
Actual feedback incorporation remains necessary; this package does not claim
that individual tests establish team collaboration.

Review questions for the instructor
1. Does the AVL analysis and experiment provide sufficient depth for Outcome 3?
2. Are the selected course-file limits reasonable for this advising scope?
3. Is retaining baseline indirect-cycle behavior appropriate for this milestone,
   or should cycle detection become a separately scoped future improvement?

Milestone Three packaging: original + enhanced source in one ZIP, with a separate
Word narrative. Original hashes are recorded in evidence/original-sha256.json.
